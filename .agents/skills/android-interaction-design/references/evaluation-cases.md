# 行为验证案例

维护者用固定输入和当前目标代码核对以下行为。人工推演不等于独立评测、设备验证或用户测试；真实试用记录输入版本、实际选择、产物和证据。测试生成物放临时目录，遵守设备排除项。

| 输入与材料 | 可观察预期 | 失败信号 |
| --- | --- | --- |
| 普通三页面工具 App 已有 Base，无路由框架 | 沿用 Intent/Fragment 等现有简单导航，说明返回及参数 | 添加 Router、KSP、路由插件或空 Navigator 包装 |
| 大型业务 App，多团队模块需统一拦截与服务发现 | 架构核实契约和依赖，评估 AndroidCoreRouters 并给增量接入方案 | 仅因页面多强制路由，或忽略实际跨模块需求 |
| DevLib 已有 Router 的 Demo 新增入口 | 复用既有路由契约、参数和入口 | 以普通项目无需路由为由移除现有 Router |
| 列表筛选页已有 Base Adapter、XPopup | 给出具体类型/调用位置，补选择、关闭与恢复语义 | 全部改 ListAdapter/BottomSheetDialogFragment |
| 表单含四项短输入，键盘后仍可用 | 根据上下文及空间评估现有弹层或页面，记录理由 | 仅凭四个字段强制全屏 Fragment |
| 三步导出，可返回修改，任务支持取消 | 区分步骤状态、草稿、任务与返回取消；交接可观察验收 | 只写 ViewPager2 与动画，不描述数据恢复 |
| 复杂详情由 BaseActivity 和列表实现 | 保留兼容的页面契约，按目标改进交互 | 禁止 Activity 或 RecyclerView 并重写无关架构 |
| 不可恢复删除与可恢复归档 | 分别确认后果与提供真实撤销，核实数据契约 | 全部立即删除并显示假 Undo |
| 明确 Figma/Zeplin 任务卡 | 沿用指定稿，仅补平台行为和组件映射 | 重新规划视觉或复制第二份交接 |
| 改图标/译文或修复纯库引擎 | 不触发完整交互设计，不新增 UI/依赖 | 强制七阶段报告或新增页面 |
| 小屏输入页、键盘、读屏与减少动效 | 说明操作可达、焦点和反馈；实现复用 Base 的 Insets | 固定下 40% 热区、重复 padding、强行动效 |
| 禁止设备操作，仅有源码 | 标注静态结论及待运行场景 | 自动 adb 或宣布运行/视觉验收通过 |
