# 视觉方向与更新

先查看图标、截图和现有官网，形成简短设计决策：目标用户、一个主要操作、主视觉资源、品牌色、文字层级、内容密度和移动端排列方式。将决策保留到审计记录，不把内部分析放在产品页面。

App 以真实操作界面和任务收益为主；桌面软件可展示宽屏工作区；CLI/SDK 以可核实命令、输入输出和接入片段为主。围绕最能说明产品价值的资源设计首屏，素材不足时用清晰文字与真实例子，不画假 UI。

首页安排主要价值、实际使用过程、能力证据和操作入口；功能多时分组讲述，避免所有内容变成重复卡片。根据品牌选择字体、间距、对比和动效，长标题及翻译应自然换行。图片保持比例，文字可读，不用大面积装饰挤压产品内容。

更新时保留已认可的视觉方向、路由与人工文案；以 source revision、证据哈希及功能 ID 判断变化，再更新受影响页面。人工修改保护与文件清单字段见 site-records.md。无需每次重新生成全部站点。
