# 官网本地验证

按输出实际技术栈执行，不要求新增 CI。

先运行 `python -B <skill>/scripts/validate_site.py --site <public-root>`。退出码 1 表示静态错误；JSON 输出包含规则编号、路径和详情。脚本检查 HTML 引用/锚点、CSS url、JSON 与部分私有文件；不执行 JS、不解析 JS 模块导入或 srcset、不访问远端，也不能证明构建和视觉通过。这些项仍按下文检查。

- 已有构建项目：运行已有适用的 build、lint 或类型检查，不随意替换包管理器或锁文件。纯静态站点无需安装框架。
- 检查 HTML 本地 href/src、CSS url、脚本导入、图片、favicon 与子页面相对路径；核对页面锚点。外部服务不可访问时记录未验证，不编造可用结果。
- 检查页面标题、主要标题、meta description、lang/dir、结构化 JSON、清单 JSON、占位符及异常编码。域名未确定时缺少 sitemap/canonical 属于已记录的发布待办，不用假地址满足检查。
- 使用 HTTP 预览而不是 file://；例如在确认输出目录后运行 `python -B -m http.server 8000 --bind 127.0.0.1 --directory <public-root>`。仅启动临时本地服务，结束时清理自己启动的进程。
- 浏览器可用时，检查约 360px 移动端与 1440px 桌面布局、键盘焦点、导航/菜单/语言切换、下载入口、长文字及横向溢出。没有浏览器则明确视觉与交互未验证，不宣称通过。
- 检查公开文件中没有凭据、机器路径、源码证据、私有配置或不应公开的截图内容。部署文件清单不能包含 `.site-audit/`。
- 例外记录具体检查项、适用路径、业务原因、替代验证及复查条件；只豁免该条目，其他检查照常执行。
- 验证报告区分代码/结构检查、浏览器验收和远端发布；报告是否提交、推送、部署。创建文件本身不证明已上线。
