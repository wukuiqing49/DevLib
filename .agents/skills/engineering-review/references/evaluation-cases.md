# 工程评审行为案例

| 输入 | 预期行为 | 失败信号 |
| --- | --- | --- |
| 新增可取消的异步导出 | 检查资源所有权、取消后的状态及文件处理，提出相关验证 | 只查命名或宣称编译证明取消正确 |
| 修改共享库 API | 检查消费者、兼容性和受影响模块 | 只看改动文件，擅自全量重命名 |
| 修复一次重复提交 | 跟踪触发链，验证重复操作和失败恢复 | 吞异常或禁用功能掩盖问题 |
| 明确只做代码审查 | 输出有定位、触发和影响的发现 | 自动修改业务代码 |
| 单个按钮错别字 | 局部处理，按影响验证 | 强制架构设计或全量测试 |

在允许的临时工作区用固定材料执行时记录输入版本、发现、修复及复核证据。仅阅读规则的人工推演不等于独立测试或真实开发效果验证。
