# 页面设计交接

主执行者维护同一份任务说明，需求、设计和实现共享目标与验收项。简单任务写在对话中；复杂任务可保存到目标项目既有任务目录。已有 Figma/Zeplin 任务卡直接补充必要字段，不再复制一套文档。

| 内容 | 最小交付 |
| --- | --- |
| 依据 | 用户目标、页面范围、设计版本/节点或现有页面、假设 |
| 层级 | 首要信息、辅助信息、主操作及次级操作，解释取舍 |
| 功能保全 | 本轮功能/原入口 → 新入口 → 操作变化 → 已实现或缺口；合并/收纳可追溯，删减须有用户依据 |
| 用户路径 | 从哪个页面进入，操作完成如何反馈、返回及恢复；重构时比较关键步骤变化及理由 |
| 交互与导航 | 本轮相关容器/弹层选型理由、导航方式、参数与结果、返回/关闭/取消语义；记录按目标架构规则选型的依据与兼容范围 |
| 基础能力映射 | 职责 → 已核实的 Base/ViewModel/Adapter/弹窗/导航/功能库类型与代码位置 → 能力缺口及最小方案；复用上游调查，不强制安装全部库 |
| 结构 | 顶部、内容区、操作区的布局与滚动关系；必要时画线框 |
| 资源 | 颜色、文字层级、间距、图标、组件对应的真实资源名与路径 |
| 风格依据 | 用户指定设计版本、项目风格规则、适用例外；区分目标、当前源码、用户认可和实机结果 |
| 状态 | 本轮涉及的加载、空态、失败、成功、禁用、选择等状态及触发条件 |
| 恢复与反馈 | 相关输入/草稿/选择/任务的归属及页面或进程重建策略、防重复提交、失败重试、撤销是否真实可用；反馈、焦点与必要动效 |
| 适配 | 内容增长、长文案、窗口变化时的行为，系统栏/键盘交给平台实现方案 |
| 验收 | 可观察结果、参考材料、验证方式和当前证据状态 |

未涉及的状态不强制增加。缺少素材或行为定义时明确缺口，不能伪造设计事实。设计预览使用实际长度内容，演示数据明确标记，不以占位符掩盖布局问题。

实现者补充组件映射、状态归属与设计差异。新增资源前搜索现有定义；继承样式必须检查最终有效属性，空样式不代表设计已定义。遇到需求变化更新原说明，避免多版本冲突。
