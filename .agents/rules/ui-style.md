# UI 风格与一致性约束

本文件为 DevLib 工作台与 Demo 的风格约束；消费项目应按自己的用户、品牌和真实资源调整，不将工作台配色或导航作为库 API 要求。设计方法由 ui-design 负责，平台实现见 ui.md，资源事实和验收状态见 ../config/ui-baseline.md。

## 职责与依据

- ui-design 主导信息架构、操作路径、布局和状态；ui-style-review 检查同一方案与实际画面的风格；Android 工作流消费交接实现。主执行者统一取舍，不产生竞争方案或循环调用。
- 用户明确指定的设计版本优先；实际平台可访问性、系统行为与数据安全约束须处理，冲突记录具体差异，不静默换稿。仅关键产品歧义需澄清，可逆细节在授权范围内决定，不增加逐页审批。
- 风格统一不授权删减功能、改变业务语义或更改消费产品品牌。重构记录本轮功能原入口、新入口和操作变化，收纳后仍可发现。
- 当前源码、设计目标、用户认可和实机结果分开记录。旧页面及未认可截图不能自动成为强制设计标准。

## DevLib 工作台方向

面向开发者，突出能力发现、接入说明、操作前提和执行结果。按架构、功能、三方与工作区的实际分类导航，模块列表服务检索，Demo 服务单项能力验证，不把内部实现事件铺成业务首页。运行结果明确区分输入、执行、产物和错误；资料与配置按需展开，必要的安全前提不能隐藏。

工作台方向不代表现有页面已经符合或被认可；不把相机、摄影客户、购物或其他消费产品流程带入通用库。

## 视觉与组件规则

| 维度 | 约束与设计空间 |
| --- | --- |
| 颜色 | 使用项目 surface/content/primary/error 等语义资源，维护明暗对应关系；同色不混用为交互、选择和成功语义；配合文字或形状 |
| 主次操作 | 按当前任务表达视觉优先级；危险动作独立，普通次级动作不全部填充强调；不机械限制全屏按钮数量 |
| 字体 | 控件与正文优先系统字体及语义文字样式；标题、正文、辅助层级稳定，允许工具页合理密度，不靠缩小文字掩盖拥挤 |
| 间距和形状 | 同类组件共用资源，组内紧、组间松，保持对齐；卡片用于真实分组或实体，不给每段文字加卡片 |
| 图标 | 同一线条/填充语言、重量和尺寸，图标动作具备可访问名称；不直接移植平台专属图标 |
| 内容 | 导航表达目的地，按钮表达动作；高频必要动作可发现，低频配置有明确入口，完成反馈与恢复路径一致 |
| 状态 | 按任务定义相关默认、选中、禁用、忙碌和错误外观；空态给下一步，错误给可行恢复，不仅依赖颜色 |
| 弹层与动效 | 弹层服务短任务或必要决策，不嵌套完整工作区；动效用于状态和空间关系，考虑减少动效，无必要不加装饰 |

具体颜色、字号、间距和圆角以目标项目实际资源为数值事实源，本文件不复制第二套 token 数值。资源缺失时设计交接提出映射及理由，实现阶段补齐。

## 验收与例外

按“规则 → 页面/资源 → 观察或测量 → 修复/例外 → 复核”记录。对比度、尺寸依据实际数值及适用平台标准，不凭截图臆造。缺少实际画面只给源码审查结论；风格通过不代表功能完整、用户认可或全部设备通过。

例外限定页面、状态、原因、替代方案及复查条件，不因个案放宽整类规则。Apple 原则可作为清晰层级、内容优先、反馈和无障碍参考；Android 单位、原生行为和组件优先，个人 Apple Skill 不复制到项目中成为竞争设计入口。
