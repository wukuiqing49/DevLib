# Agent 执行规则

## 通用流程

1. 先分析原因、目标模块、现有实现和影响范围。
2. 读取任务 Workflow 声明的 Rules、Skills 和项目事实文件。Android 功能开发按根 AGENTS.md 的必读要求执行，不因改动简单而跳过 Base、UI、国际化、适配与中文注释检查；不适用项说明原因。
3. 优先最小修改，不扩大到无关文件。
4. 执行受影响范围的最小验证；高风险修改扩大验证。
5. 汇报修改文件、原因、验证结果、未验证项和剩余风险。

## 需求与结果交接

规则维护约束的完整定义，Skills 提供方法，Workflows 选择能力与交接顺序；任务说明记录本轮决策和证据。下游引用上游已完成的结果，不重新询问、重复生成或启动相互调用。新增建议不得自动变成所有任务的硬约束。

- 目标、用户或成功标准不明确的功能/优化请求，读取 `.agents/skills/clarify-requirements/SKILL.md`；明确的小修复直接执行，避免为所有任务生成需求文档。
- 非平凡功能、跨模块改动、复杂 Bug 或明确代码审查，读取 `.agents/skills/engineering-review/SKILL.md`，在方案和实现阶段按实际风险评审；机械修改只做局部检查。
- 功能交付、复杂修复、版本验收或明确验收请求，读取 `.agents/skills/acceptance-review/SKILL.md`，整合有效证据后判断本轮完成状态；简单任务保留紧凑核对，不强制独立报告。
- 新增、重构关键操作/接入流程或明确要求体验审查时，读取 `.agents/skills/review-user-journey/SKILL.md`，实现前检查方案路径，完成后对照实际产物验收。同一任务复用已有分析，不重复加载或重复出报告。
- 主执行者负责维护目标、选择适用能力和解决意见冲突：用户明确要求与项目硬约束优先，建议以事实和验收条件为依据；无法同时满足时说明取舍，关键产品决策交由用户决定。
- 默认由主执行者按需切换需求、开发、设计和用户视角；独立子智能体仅在用户或适用指令明确授权时使用。审查先看原始需求和实际产物，范围内修复后复核，不把角色轮流发言当成交付。
- 完成时用验收条件对应证据和通过/失败/未验证状态，优先报告成果与剩余问题；简短任务可以合并为一句，不以固定篇幅或角色数量衡量质量。

## 技术栈适用范围

- DevLib 已是 Android 多模块库工程；修改 core、app 或构建配置时按根目录真实 Gradle 模块验证，修改工作流脚本和模板时另执行对应脚本校验。
- 下列 Gradle、Manifest、资源、UI 和设备要求仅适用于对应 Android 任务。其他技术栈使用目标项目已有工具链。

## Bug 修复

- 先判断根因并指出关键错误行或模块，再给出最小修复。
- 需要代码时提供可直接使用的完整实现，不只给无法落地的片段。
- 检查是否需要同步修改 Gradle、Manifest、ProGuard/R8 或资源配置。
- 不通过删除功能、吞掉异常或降低 SDK 规避问题。

## 验证

- 默认运行受影响模块的最小 compile/test 任务。
- 涉及 app 壳、manifest、签名、打包或 release 时运行 app 级验证。
- 涉及资源、strings、plurals 或 raw HTML 时检查编码、占位符和脚本语法。
- 涉及 UI、列表、分页、弹窗或字体时说明小屏幕、长文案、字体缩放和生命周期覆盖情况。
- 涉及 native、release、签名或 16KB page size 时明确验证范围和剩余风险。
- 因环境、凭据、设备或网络无法验证时，说明原因，不把未执行项表述为通过。

## Skill 验证与 CI 管理边界

- Skill 中的验证脚本默认用于本地检查。安装 Skill、初始化工程、开发功能或执行验证，不构成创建或启用 GitHub Actions 的授权。
- 只有用户明确要求配置 CI 或远端自动检查时，才新增工作流或调整 GitHub Actions 触发条件；新增工作流已获授权但未明确自动触发需求时，仅使用 `workflow_dispatch`。
- 已有工作流保留原配置；未经用户要求，不删除任务、不修改触发方式。纠正本次任务中未经授权新增的工作流时，应确认其尚未提交且由本次任务创建，保留用户原有文件。
- 本地仍按任务 Workflow 执行必要验证，不因没有远端工作流或关闭自动触发而跳过检查。
- 通用校验规则应允许明确、可追踪的项目业务例外。例外至少记录规则编号、适用路径、业务原因、替代验证方式和复查条件，并限定到具体条目；不得为通过检查破坏实际功能，也不得直接关闭整类检查。
- CI 配置变更后检查 YAML、实际触发条件与 Git 差异；汇报是否已提交、推送、远端生效。仅本地解析或构建通过，不代表远端 CI 通过。

## 输出

- 所有回复使用中文，按“结论 -> 原因 -> 方案”组织。
- 代码注释优先中文；不输出真实密钥、证书、token 或隐私数据。
- 最终说明修改了哪些文件、为什么修改、执行了什么验证以及未验证风险。
