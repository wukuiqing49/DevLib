# DevLib 页面分析与视觉优化

日期：2026-10-27。范围：开发者工作台及 19 个能力入口共享的宿主 UI；不修改独立基础库实现，不改变库 API、现有流程、路由或凭据边界。

## 原有问题与本次处理

| 问题 | 原因 | 实现 |
| --- | --- | --- |
| 绿按钮、紫灰导航及标题背景混用 | 主题只配置 Primary，其余沿用 Material 默认色；Base 标题独立取色 | 在 feature_res 统一深浅主题语义色，App 映射 Material 颜色及 Base 标题资源 |
| 每个动作同样醒目 | 所有页面共用填充按钮 | 默认描边次操作，生成/上传/连接/登录等使用 Primary，停止/拒绝/退出等保留文字并使用错误色 |
| 卡片过高、操作分散 | 开始与收藏分别独占一行 | 工作台卡片内边距 16dp、圆角 16dp，两个动作等宽并列，自然换行 |
| 输入标签拥挤 | 输入控件自身有顶部间距，容器间无明确统一间距 | 43 个 TextInputLayout 显式使用共享圆角/填充/12dp 容器间距；子输入取消重复顶部间距 |
| 未执行时出现一组不可用产物按钮 | 输出区只判断 enabled，始终显示操作 | 结果卡片统一分组；存在文件产物才显示打开/分享/另存/继续，执行中保留取消 |
| 深色返回箭头几乎不可见 | Base 默认位图未随主题着色 | 宿主沿用 Base.setLeftIcon 接入主题化、RTL 自动镜像矢量图，并设置无障碍说明及至少 48dp 点击宽度 |
| 横屏工具列表不可见 | 固定页头占满可用高度 | CoordinatorLayout + Material AppBarLayout 可折叠页头；短窗口默认收起，支持下拉恢复搜索和分类 |
| 键盘可能遮住表单 | 标题页默认不请求 IME 避让 | 仅在宿主覆写 shouldApplyImeInset，继续使用 Base 唯一底部 owner |

## 色彩与层级

- 浅色：背景 #F5F7FC、卡片 #FFFFFF、主色 #2458C6、正文 #192338、辅助色 #146C70。
- 深色：背景 #101722、卡片 #192331、主色 #AFC6FF、正文 #E5ECF7、辅助色 #8DD4D3。
- Primary 用于当前主要操作；Secondary 用于元信息；Error 只标记停止、拒绝等操作语义，不替代文案。
- 独立定义背景、卡片、表单填充、边框、主次文字、主色容器及错误容器，避免混用未配置的默认色。
- 12 组正文/辅助文字/按钮/错误文字与对应背景的计算对比度均达到 4.5:1。边框及所有运行态不包含在这项计算中，不能据此宣称整页无障碍验收通过。

## 各入口的应用范围

| 页面/能力 | 主要操作与呈现 |
| --- | --- |
| Base / Utils / Network / XPopup | 保留各自状态、文件摘要、网络请求与弹窗体验；共用主次操作层级 |
| Router API / Annotation / Processor / Plugin | 跳转为主操作，检查为次操作；保留四个基础模块独立演示 |
| 局域网分享 | 开始分享为主，审批为次，拒绝和停止明确使用错误色 |
| 上传 | 文件选择与连接测试为次，上传为主；凭据输入仍不自动发起网络 |
| NAS / USB | NAS 连接、USB 授权和上传按阶段强调；上级目录、选择、探测为次；无自动访问真实存储 |
| 归档 | 压缩与解压并列保留为主操作；素材选择及示例为次 |
| 图片处理 | 渲染为主，编辑、撤销与示例为次；保留水印等原有模式 |
| 二维码 | 生成与识别并列；选择素材为次，不自动打开相机 |
| 元数据 | 读取和写入副本按阶段强调；保留原始文件及事务边界 |
| PDF | 生成主操作、反转和选图次操作；统一结果预览与文件操作卡片 |
| Office | Word / Excel 并列主操作；行列编辑次操作，移除列明确使用错误色 |
| Google | 登录、购买和评分条件检查分区强调；恢复、诊断、反馈及退出保留原流程，不自动触发外部事务 |

lib_operations 是内部支撑，不新增业务页面。19 个入口使用 20 个页面布局（含路由目标页），共享样式会统一影响这些入口；不代表每个业务流程都已真机验收。

## 架构、文案与适配

使用项目 android-ui-workflow、android-project-architecture-workflow、android-i18n-workflow、android-build-workflow；真机复核遵循 android-functional-test-workflow。DemoActivity 继续继承 BaseVMTitleActivity，CatalogFragment 继续继承 BaseVMFragment，列表继续使用 BaseRecyclerViewAdapter，复杂状态仍留在既有 ViewModel。

普通页面保留 Edge-to-edge，不自动隐藏系统栏。顶部由 CommonTitleBar 消费状态栏 Insets；底部/横向/IME 由 Base 页面统一处理，BottomNavigation 不重复添加系统高度。没有新增一套 Insets 或 Activity 基础封装。

新增返回说明同时提供默认中文与英文。业务文案、资源 key、公开 API 和路由未重命名。类与方法变更保持中文 KDoc。横向操作使用等宽弹性布局及 wrap_content 高度，不用固定屏幕尺寸或锁定方向规避适配。
