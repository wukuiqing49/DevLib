# Google 支付组件设计方案

日期：2026-10-30。范围：无需自建后台的 Google Play 客户端购买、恢复、官方兑换入口、付费状态输出、Activity 与 BottomSheet。此文与交互稿是设计交付，尚未实现 Android 支付 UI。

交互稿：`design/billing/index.html`。价格、权益、商品和状态均为示例，不代表 DevLib 提供付费权益。无需网络，无真实购买、兑换和订单数据写入。

## 设计判断与依据

采用 apple-design Skill 的层级、克制、可访问性和短任务原则，保留 Android 返回、TalkBack、48dp 触控区、Roboto/系统字体与原生 Play 收银台，不引入 SF 字体、Apple Pay 标识或 iOS 专属交互。

- `layout.md › Visual hierarchy`：“Order content by relative importance.” 顺序为价值、方案、披露、主操作。
- `typography.md › Conveying hierarchy`：“Minimize the number of typefaces you use”。使用单一系统字体，由字号、字重区分层级。
- `buttons.md › Style`：“Keep the number of prominent buttons to one or two per view.” 这里只保留一个实心主操作。
- `sheets.md › Best practices`：“Display only one sheet at a time from the main interface.” 不叠加自定义购买确认弹层；Play 官方窗口由 SDK 管理。
- `modality.md › Best practices`：“Always give people an obvious way to dismiss a modal view.” 提供关闭、返回和适用的下滑关闭。
- `writing.md › Best practices`：“Write clear error messages.” 错误在页内解释并给出重试动作。
- `accessibility.md › Vision`：正文对比度至少 4.5:1，状态不只依赖颜色，支持文字放大。

以上为本地 Skill 所附参考中的短引文。具体配色、间距及文案为本项目设计判断。Apple 平台规则不作为 Android 强制规范。

## 视觉语言

沿用现有 feature_res 色板，由宿主主题注入可选 UI 库，禁止 UI 库依赖 feature_res。中性背景、实色表面、项目蓝色。唯一强调是选中的方案和购买动作。不加入皇冠、闪烁折扣、倒计时或虚构推荐标签；取消了初稿中无业务依据的推荐角标与装饰性大渐变。

| 页面背景 | #F5F7FC | #101722 | — |
| 表面 | #FFFFFF | #192331 | — |

Android 字号：主标题 30sp（弹层 24sp），套餐名称/主按钮 16sp，正文 15–16sp，价格 20sp，披露 13sp。正文行高约 1.6。触控区最小 48dp、主按钮最小 54dp，可随字体增长；外边距 24dp，紧凑窗口可减至 16dp，间距采用 4/8/12/16/24/32dp。卡片圆角 18dp，弹层顶角 28dp。

## 两种形态

紧凑宽度：

```text
Activity                     BottomSheet
系统栏                       宿主当前业务上下文
标题 / 关闭                  遮罩
品牌符号                     拖动柄 / 关闭
权益标题与简介               简短权益标题与简介
关键权益                     套餐列表（同一组件）
套餐列表                     页内状态反馈
可滚动内容                   可滚动内容
价格与续订说明               价格与续订说明
购买按钮                     购买按钮
恢复 / 兑换                  恢复 / 兑换
条款 / 隐私                  条款 / 隐私
导航安全区                   导航安全区
```

常规窗口 >=600dp：Activity 居中最大 840dp，左右各 24–32dp 安全间距，左列权益、右列套餐和操作；高度紧张时整页滚动，避免固定操作区占满窗口。BottomSheet 居中限制最大 560dp，保留同样内容，不拉宽卡片。此宽屏布局为 Android 实现规格，当前交互稿主要预览手机形态。

BottomSheet 按内容与实际可用窗口确定初始高度，优先约 75–85% 的可用高度，可展开；小屏、横屏和大字体允许接近全高，不固定整屏像素。拖动柄是展开与关闭的辅助，不是唯一操作方式。关闭不停止进程级确认补偿；不要关闭单例 Billing 连接。切换展示方式不改变选择和报价模型。

## 状态与交互

默认不预选付费方案；宿主若明确提供默认项，仍需完整展示价格和披露。没有 Play 实时报价时禁购，不使用 fallbackPrice 启用购买。

| 状态 | 内容与主操作 | 对外付费结果 |
| --- | --- | --- |
| 加载 | 获取真实报价，保留关闭 | 未知或保留旧快照 |
| 就绪未选 | 套餐卡片，提示选择 | 不改变已有状态 |
| 就绪已选 | 明确总价/周期、继续购买 | 不改变已有状态 |
| 拉起 Play | 防重复点击、接受 SDK 回调 | 不提前置 Pro |
| 用户取消 | 页内“购买已取消，可重新选择” | 保留原有状态 |
| 待付款 | 明确尚未生效、允许刷新 | 未付款订单不授权 |
| 核对中 | 禁止重复发起、允许关闭 | 未确认不报成功 |
| 已拥有 | 付费类型、管理入口、完成 | 返回真实商品及付费快照 |
| 离线缓存 | 标明上次记录，提供重新核对 | 携带 source 与 freshness |
| 查询失败 | 错误及重试，不判定免费 | UNKNOWN/保留旧快照 |
| 暂无商品 | 恢复、兑换、重新获取 | 不代表无历史购买 |

订阅披露显示 Play 返回的实际周期与价格；未来支持试用及首期优惠时，需同时显示后续续订价格和阶段。一次性购买不得套用订阅续订文案。按钮写“继续购买 · 总价/周期”，明确后续会进入 Play 官方确认。恢复、兑换不以成功 Toast 代替核对结果。

兑换：打开 Play 官方入口 → 返回前台 → 刷新购买记录 → 更新付费快照。不自行收集兑换码，不根据返回 Intent/返回前台推断成功。条款、隐私、管理订阅均有清晰出口，外部返回保留套餐选择并重新校验报价。

## 状态输出与模块边界

core_google 保留引擎及兼容 API，新增统一可观察快照的具体 API 在实现时确定。快照至少包含 isPro、查询状态、订阅/一次性商品 ID、待付款、来源及核对时间；不能从未知到期时间推导到期日期。操作事件独立表达取消、失败及需恢复，不把取消等同于免费。

可选 core_google_ui 依赖 core_google、现有 Base 和 XPopup，不依赖 app/feature。Activity 通过 Activity Result 输出关闭时快照；BottomSheet 通过可释放回调输出；持续状态订阅由 core_google 提供，关闭页面后订单处理仍可完成。宿主按商品映射实际权益，组件不写入产品 Pro 门禁。测试页放 feature_demo_google。新增正式模块后需同步事实清单、发布与独立消费验证。

## Android 17 与窗口策略

Activity 默认 Edge-to-edge，保留可见系统栏，不把支付当作视频全屏。复用 Base：明确顶部 Toolbar 为 top inset owner；固定操作区为 bottom inset owner，取 max(IME, navigationBars)，处理 displayCutout/captionBar，父子不重复叠加。

BottomSheet 先审查 XPopup 实际 Window 和 Insets owner；宿主处于隐藏系统栏的全屏模式时，弹层展示期间使用适合支付的可见系统栏，保存并在退出恢复宿主明暗及隐藏策略。宿主显式请求全屏 Activity 时采用 AndroidX 控制器，提供关闭与边缘临时唤出，不能干扰 Play 窗口。

旋转/重建保留选择、展示形态和可恢复状态，重新核对报价，不自动再次提交购买。冷启动必须由宿主恢复运行时商品配置。处理预测性返回、横屏、多窗口、刘海、三键/手势导航、TalkBack、RTL、英文及 200% 字体。系统减少动画时直接切换状态，普通情况下只用短淡入/弹层位移，不做循环装饰动画。

## 验证边界

交互稿检查覆盖两种形态、深浅色、状态切换、选择与禁购、关闭/重开及浏览器布局；它不是 Android 实现，不验证真实拖拽、窗口 Insets、Activity Result、Google Play、Pro 授权或设备行为。Android 实现需遵循项目架构/UI/国际化/构建与功能测试 Skills，默认不执行 adb。未新增 CI，未提交或推送。


## 第二轮优化（2026-10-30）

- 缩短标题及权益摘要，降低首屏介绍高度；套餐总价与周期采用等宽数字，提高扫读效率。
- BottomSheet 使用独立表面色与轮廓，深色时明确区分遮罩、宿主与弹层；点击拖动柄可预览展开/收起。
- 底部增加已选方案摘要与 Play 付款说明，兑换入口缩短名称；保持续订披露在购买按钮上方。
- Pro 状态替换推销标题并展示已拥有方案、管理订阅与完成；补充用户取消状态，保留原付费状态语义。
- 关闭后支付内容设置 inert，避免键盘进入不可见内容；重新打开恢复交互，支持 Escape 关闭。
- 浏览器 12 项状态/操作断言通过；360px 视口、大字号下检查横向溢出、滚动与末项可达性。截图已更新。原型不验证 Android 原生行为或真实付款。


## 兑换页面补充

交互稿点击“兑换码”进入独立的兑换说明页，提供官方兑换入口、已有兑换的核对操作，以及返回后的核对中/已生效/未查到购买/核对失败视图。结果切换按钮明确标注为设计预览，不产生真实订单。成功预览可返回支付页的 Pro 状态。兑换说明特别区分应用优惠码与 Play 礼品卡余额，避免把余额充值误报为付费权益。截图：design/billing/redeem.png。

已检查兑换入口可达、核对视图、失败视图、成功后 Pro 状态与返回。真实兑换及 Android 页面仍未实现。


## 多语言与流程优化（2026-10-30，覆盖前述原型版本）

当前原型已改为 HTML/CSS/交互 JS/语言资源分离。14 个语言区域、每语言 63 个键，共 882 项；完整列表与验证命令见 design/billing/README.md。不静默以英文填补缺译；已覆盖动态状态、无障碍名称与原型说明。翻译初稿未经母语及法律审校，不能标记为正式发布文案。

兑换改为同层页面替换，移除原先双出口和三步长说明。保留简短说明、账号提示、官方兑换、已有兑换核对；核对中禁止重复操作，模拟结果下拉框放到原型控制区。进入兑换将焦点移动到标题，返回恢复到兑换入口；展开高度与支付弹层一致。

阿拉伯语支持 RTL、返回图标方向和价格隔离；价格统一使用 USD 示例金额，各语言只做 Locale 格式化，正式 Play 报价规则不变。成功示例仍以年度订阅演示，不是底层将所有购买映射为年度 Pro。恢复使用独立的购买核对状态，避免误显示加载商品。

已完成多语言浏览器状态检查、320px/主要文字 200%/两种形态/两种主题布局矩阵；56 个支付布局与 280 个兑换状态布局通过几何检查。修复德语长词和俄语标题溢出。通过不代表母语审查、全字体矩阵、原生 Android Insets、设备或真实 Play 功能验证。当前只优化设计稿，不宣称 core_google 已具备这些 UI 或语言资源；未提交推送。


## 原生落地更新（2026-10-30，覆盖前述仅原型状态）

按用户最新要求，原生支付 UI 和引擎统一放在 `core/thirdparty/core_google`，没有新增 core_google_ui 模块。实现 GoogleBillingUi.openActivity / showBottomSheet、GoogleBillingContract、GoogleBillingStatus，复用既有运行时及页面配置。采用 BaseVMActivity、BaseViewModel、BaseRecyclerViewAdapter、XPopup、XML/ViewBinding，14 个语言区域资源、日夜配色、官方兑换与恢复流程；不依赖 feature_res。

HTML 继续作为设计参考，原型中的模拟价格和成功状态不参与原生支付。原生仅展示真实 Play 报价，购买前重查报价；兑换返回查询实际购买，待付款与未知不授予 Pro。宿主负责商品、条款、账号与权益映射。接入示例及不支持项见 core/thirdparty/core_google/README.md，实际验证见固定测试报告。
