# Agent 与 Skills 整体分析及优化

日期：2026-10-26。范围为当前 DevLib 的 AGENTS.md、.agents 规则、工作流、Skills、模板和本地验证工具；不是重新迁入功能库或改写基础库。

## 结论

现有体系已覆盖架构、UI、国际化、构建、设计还原与测试。主要问题是规则分层不一致、模板未跟进中文注释、校验范围与实际项目边界不一致。首次审查完成规则与工具修正；后续已补齐此次审计范围内的 241 项中文注释及两个语言目录各 81 项缺译，见文末收尾记录。

## 发现与处理

| 问题 | 本次处理 |
| --- | --- |
| 根入口禁止 core 依赖 feature，但架构规则允许 feature_res | 统一禁止依赖所有宿主 feature，新增回归测试；基础库源码未改 |
| 所有功能开发一律走页面流程 | 新增 develop-feature 共同入口，保留 Base、中文注释基线，再按实际影响加载 UI、国际化、构建和测试 |
| 生成代码没有满足中文注释规则 | Application、MainActivity、FeatureAppEntry 模板补齐中文 KDoc，加入模板契约测试 |
| Base/注释/资源化只靠人工提醒 | 新增按选中文件检查的源码审计工具，支持明确文件、Git 基线、JSON 报告和具体条目例外 |
| Figma 默认放宽 Fragment/Adapter，并把底部导航强制当作分页 | 移除聚合入口默认豁免；只有明确分页要求才强制 ViewPager2 |
| 外部项目检查借用了工具仓库的档案/目录配置 | 分开工具结构与目标档案验证，未提供目标档案时明确标记未验证；不再借用工具仓库模块配置 |
| 未注册的配置目录也被扫描 | 只收集 settings 已注册且存在的宿主模块；动态 settings/projectDir 映射仍需人工确认 |
| 测试流程先检查 adb，忽略用户排除项 | 先读取执行策略和排除项，项目档案保存设备命令排除策略 |
| 官网 Skill 存在个人版与项目版同名 | 明确项目本地版本优先，不修改个人版本 |
| Zeplin 实现与项目规范脱节 | 实现前读取目标 Android/UI/架构/i18n 规则，已有实施授权不再重复等待确认 |

## 验证结果

- 公共脚本测试 31 项、生成器测试 8 项、Figma 脚本测试 4 项，合计 43 项通过。
- Agent 结构验证通过。聚合静态检查覆盖 9 个宿主模块；构建配置/UI 零警告，架构 2 项原有启发式警告，i18n 2 项缺译警告。
- 源码审计检查当前 Git 工作区中 67 个变更/新增主源码或 XML 文件，发现 241 项 DOC001 待复核项，审计命令退出 1；没有将失败隐藏为通过。证据见 testing/evidence/2026-10-26-skill-optimization/source-audit.json。
- feature_app 的 values-en、values-zh-rCN 各缺 81 个显式翻译键，目前使用默认资源 fallback。本轮未补译，也不将 fallback 当作语言验收。
- git diff --check 通过。未执行 Gradle 编译、设备或视觉测试；本轮修改工具与模板，生成器测试在临时目录进行。历史构建结果不能算作本轮重测。

## 检查边界与后续顺序

源码工具检查选中文件全文，不能把全部报告项认定为本轮引入。它识别常见声明、直接平台继承及部分可见文案，不能替代 Kotlin/Java 编译器、间接继承分析、翻译审校或屏幕适配验证。复杂签名、动态文案、Toast/Compose 需人工检查。例外须精确到路径、规则、行号，并记录原因、替代验证和复查条件。

后续业务修改按功能模块逐项复核注释与翻译，结合真实方法职责补文档；UI 按小屏/横屏/大字体/RTL/Insets 等逐项验收。不要为通过脚本批量添加无意义注释，不改变公开 API，也不要将基础库纳入机械改写。

本轮未修改 core 源码、未新增或调整 CI、未提交、未推送。Android 17 配置及此前的 App 改动保留原状；本轮没有重新核验平台发布状态。
